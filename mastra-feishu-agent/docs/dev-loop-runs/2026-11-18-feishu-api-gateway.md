# 日程时分修复与统一飞书 API 入口

## 原因及范围

用户在内网授权成功后，要求今天 11:00–12:00，实际创建为当天 21:40–22:40。代码复现发现 `reconcileRelativeCalendarDate` 仅校正日期；日期相同时直接返回模型时间，未按原消息重建时分。新增同日错误时分、中文时段、标题含相对日期、OAuth 续办到实际 API 请求的回归覆盖。完整开始/结束时间的编辑也使用公共资源操作入口校正。

此前 Agent 工具表没有通讯录或参会人入口。飞书后台开通权限只能允许 API 调用，不会使模型自动拥有接口定义。旧能力清单来自会话回复而非运行时工具表。

## 实现

- `clock-range.ts` 从明确单一时段提取时分；原消息北京时间决定日期。授权前保存正确时段，授权恢复仍用原消息时间，已确认的写入不重新解释。
- `scripts/generate-feishu-catalog.mjs` 从已安装的官方 SDK JavaScript 请求定义及 TypeScript 参数声明生成离线目录。当前 SDK 1.76.0 生成 1610 条 JSON API 定义，运行时过滤凭证管理端点。另纳入官方文档中 SDK 未提供的旧版姓名搜索接口。构建前自动生成，无运行时公网依赖。
- `office_discover_apis` 按关键词检索接口及分页，按 ID 获取完整参数 schema；`office_call_api` 复用统一传输、调用身份、OAuth 续办、操作审批和状态存储。新增 SDK JSON 接口无需新增 Agent 工具函数。
- 请求必须匹配目录方法、路径和参数 schema，不接受任意 URL、请求头或凭证；动态路径段编码并拒绝路径穿越。GET 直接读取，其余方法都需确认（包括 POST 查询），写入超时不自动重试。输入限制为审批卡可完整展示的大小，过大查询结果提示缩小范围/分页。
- 用户身份按已知范围及真实权限错误请求增量授权；已申请相同范围仍被拒绝时提示检查应用发布权限，避免重复授权循环。应用身份拒绝不自动变成用户授权。接口 404/405/501 沿用明确的私有化版本不支持提示。
- `office_recent_calendar_events` 按请求者和当前会话回读已成功创建日程的真实 ID，供后续编辑、添加同事使用；不借用其他人的记录。
- `office_capabilities` 调用 Agent 的 `listTools` 获取当前工具（含配置的 MCP 和定时工具），补充网关群聊/私聊总结、备份等能力。提示词要求先检索/尝试，再根据真实返回说明权限，不得凭旧清单拒绝。

## 边界与部署

统一入口覆盖目录中的 JSON 业务 API，不能保证“全部飞书 API 无条件可用”：内网版本、应用权限及可见范围、用户 OAuth、资源 ACL 均影响结果。文件上传/流式下载及凭证管理需专用适配；目录会剔除 SDK 中的流式和 multipart 请求。已有日历/任务写入走专用工具以保留时间校验；参会人操作可通过统一入口。复杂多日期、多时段自然语言不由单日时分解析器强行重写。

内网部署后，姓名搜索使用 `contact.user.search`，用户范围为 `contact:user:search`；应用身份通讯录列表使用应用已开通权限。参会人新增使用 `calendar.v4.calendar.event.attendee.create`，默认用户身份、`calendar:calendar`、`user_id_type=open_id`，重名时先确认目标人。应用后台需实际开通并发布相应权限。

本次没有连接内网租户发送邀请或修改既有日程，没有重启用户网关。更新代码后需在内网构建并重启网关，通过真实账号验证私有化接口与授权范围。
