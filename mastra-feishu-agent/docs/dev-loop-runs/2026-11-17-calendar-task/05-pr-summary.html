交付内容

  • 个人/共享日历查询、共享日历增改删，以及日历内日程的完整增删改查。
  • 请求者任务的查询、新增、编辑、完成/恢复和删除，新建个人任务自动指定请求者为负责人。
  • 缺少权限时先发授权确认卡，确认后打开 OAuth 链接；回调后继续读取或生成写入确认卡。
  • 授权打断前置查询时，保存原始请求和消息时间，查询后通过持久化队列继续完成需求。

用户流程

发起请求 → 授权确认卡 → 打开授权页面 → 校验账号 → 继续原请求 → 写入确认卡（仅写操作）→ 返回结果

取消、撤回、过期、重复点击与服务重启均有保护。资源共享权限由所有者管理；授权本身不授予 owner/writer 权限。

# 日历与任务用户授权

## Goal
飞书机器人查询、新增、编辑、删除个人/共享日历、日历内日程及用户任务；缺少授权时先请求用户审批，确认后提供 OAuth 链接，回调后继续原操作。

## User-visible Behavior / Acceptance Criteria
- 日历列表、详情、日程列表/详情及任务列表/详情支持用户身份；明确共享日历支持应用身份。
- 日历实体和日程分别提供增改删，不能删除个人主日历；任务支持增改删和完成/恢复。
- 未授权先发卡片，确认才生成链接；只有原请求者、原会话、原卡片可确认。
- OAuth state 一次性、有时效、绑定请求者；错误账号、拒绝、撤回、重启中断不执行写入。
- 授权成功恢复保存的具体请求。读取直接返回结果；写入沿用现有操作审批。
- 明确资源 ACL 不足时说明联系所有者；不隐式借用应用身份，也不重放结果不明的写入。

## Constraints / Assumptions
沿用 TypeScript、Mastra、SQLite、飞书 SDK 和现有 HTTP 回调。OAuth 链接由用户在飞书客户端打开。资源 ACL 不能通过 OAuth 自动授予。旧审批/旧权限流程兼容，不迁移或重放历史请求。私有化接口仍需租户实测。

## Non-goals
自动修改共享成员或 ACL、递归日程批量处理、任务清单管理、部署/提交代码。

用户要求两项 CRUD 与授权续办；已确认同时包含日历实体与日程。main，base_sha 50946b3763528f9a13cf8e9b38aa0769ce2575da，开始时工作区干净。
