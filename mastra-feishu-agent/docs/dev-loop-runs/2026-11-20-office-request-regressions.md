# 飞书任务检索、日程时间及审批回复修复

## 复现与原因

- 提示词使用 `office_discover_apis` / `office_call_api`，而模型工具键为 `discoverFeishuApisTool` / `callFeishuApiTool`。既有指令仅建议检索，不能阻止模型直接声称无工具。内部 `task_write` 还容易与飞书任务混淆。
- 日期与时钟解析在“主题是”处截断整个消息，导致“创建一个日程，主题是xxx，时间为今天18:00-19:00”丢失时间依据。仅补充“改为创建日程”时，旧实现也没有可信的上一轮时间来源。
- 网关在 Agent 结束时发送累积文本，普通办公审批没有像下发业务一样抑制重复回复。用户可能已确认执行，模型的过时“请确认”仍被发送。

## 修改

- 模型工具键与指令统一为 `office_*`；旧键只保留在兼容注册表。飞书操作请求首步指定目录检索，检索完成后解除限制，审批恢复不会反复强制检索。明确区分内部工作清单和飞书任务；支持“创建任务”等无空格中文查询。
- 时间解析忽略主题/描述中的日期，遇到后续明确的时间字段恢复解析。任务和日程共用字段筛选，继续在审批前、OAuth 续办时按原消息时间校正。
- 保存每个请求者、会话最近一次明确创建请求的原始时间信息。30 分钟内明确把任务改成日程（或相反）可继承，跨午夜仍锚定原消息；新时间覆盖旧时间。过期、撤回、跨用户或跨会话不继承，缺少依据时直接追问。`schedule_sources` 表在启动时自动创建。
- 同一消息已产生办公审批卡后，以卡片状态为准，不再发送模型累积的过时状态文本；卡片发送失败仍可反馈错误。

## 验证范围

回归覆盖题目在前/时间在后、模型传入 2027-01-15 11:20–12:20、校正后的审批载荷与真实 API 请求、代理请求中的强制目录检索、审批状态先于模型结束、卡片发送失败、跨午夜类型更正、撤回及会话隔离。使用模拟模型代理和飞书传输，未对内网实际账号执行写入；内网仍需更新代码、重启网关后验证。
